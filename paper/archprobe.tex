\begin{abstract}
Syscall-based behavioral detection systems are trained and deployed
predominantly on x86 infrastructure, yet modern cloud and edge deployments
span both x86 and ARM architectures. This paper asks whether a classifier
trained on x86 syscall traces can generalize to ARM without retraining.
We present \textbf{ArchProbe}, a controlled measurement study that collects
\texttt{strace} behavioral traces from 20 containerized workloads (10 benign,
10 malicious-pattern) on both \texttt{x86\_64} and \texttt{aarch64} platforms,
then evaluates seven transfer experiments using a Random Forest classifier with
leave-one-out cross-validation and bootstrap confidence intervals. All tested
representations---raw frequency, bigrams, abstract category normalization, and
first-order Markov transition features---fail to achieve reliable
cross-architecture detection (bootstrap means 48--53\%, chance\,=\,50\%).
Leave-one-out evaluation of the within-architecture baseline yields
53.3\%\,$\pm$\,49.9\%, revealing that the dataset itself (N\,=\,15) is too
small for reliable classification. Additionally, an extended 131-syscall
category mapping reveals that a prior 65\% normalized-feature result was
partially an artifact of an incomplete mapping: unmapped ARM-specific syscalls
inflated a discriminative \texttt{other} category; with the corrected mapping
the estimate falls to 55\%. These findings motivate larger, natively collected
multi-architecture datasets before drawing conclusions about architectural
portability of behavioral detection.
\end{abstract}

% -----------------------------------------------------------------------
\section{Introduction}
% -----------------------------------------------------------------------

Syscall-based intrusion detection has a long history in systems security.
Tools such as Falco, Sysdig, and academic systems like Optimus~\cite{optimus}
operate by observing the stream of system calls a process makes and classifying
whether the pattern is benign or malicious. The implicit assumption in every
deployed system is that the model trained on one machine generalizes to others
running the same workload.

This assumption silently breaks across CPU architectures. An \texttt{x86\_64}
Linux binary and its \texttt{aarch64} equivalent may use different system calls
to accomplish the same task: \texttt{mmap} vs.\ \texttt{mmap2}, \texttt{stat}
vs.\ \texttt{newfstatat}, or \texttt{clone} vs.\ \texttt{clone3}. ARM's
expanded syscall table and different calling conventions mean that the raw
string identifiers of syscalls differ even for identical logical operations.

With ARM server adoption accelerating---AWS Graviton instances, Ampere Altra
deployments, and Apple Silicon development machines---this assumption is
becoming load-bearing infrastructure debt. ArchProbe is a measurement study
designed to quantify the failure mode, evaluate four feature representations,
and honestly characterize what can be concluded at small data scales.

\textbf{Research questions:}
\begin{itemize}
  \item \textbf{RQ1:} Do raw, bigram, or normalized features yield
    architecture-invariant behavioral signatures?
  \item \textbf{RQ2:} Do first-order Markov (transition) features capture
    sequence-level invariants that survive cross-architecture transfer?
  \item \textbf{RQ3:} Is early detection viable---does observing more syscalls
    help a cross-architecture classifier?
  \item \textbf{RQ4:} How does syscall-to-category mapping completeness affect
    normalized feature accuracy?
\end{itemize}

% -----------------------------------------------------------------------
\section{Related Work}
% -----------------------------------------------------------------------

\textbf{Syscall-based anomaly detection.}
The use of system call sequences for intrusion detection dates to Forrest et
al.~\cite{forrest1996}, who proposed normal behavior profiles from syscall
sequences. Subsequent work explored bag-of-syscalls, n-gram models, and neural
sequence models~\cite{abed2015}. These techniques underpin modern container
security tools.

\textbf{Optimus.}
Optimus~\cite{optimus} reduces container attack surface by statically filtering
syscalls. Our work asks what happens when a \emph{learned} policy must transfer
across architectures.

\textbf{Cross-architecture analysis.}
Prior work on architecture-independent malware analysis focused on binary
similarity. To our knowledge, no prior work has measured syscall-level
behavioral portability for containerized workloads with bootstrap confidence
intervals or studied the effect of mapping completeness.

\section{Methodology}
% -----------------------------------------------------------------------

\subsection{Testbed}

All traces are collected inside Docker containers using
\texttt{strace -f -e trace=all}. ARM traces use Docker Buildx with QEMU
userspace emulation (\texttt{linux/arm64}) on an \texttt{x86\_64} host.

\subsection{Workloads and Data}

20 workloads (10 benign, 10 malicious-pattern); all malicious workloads are
simulated in isolated containers. Five x86 benign traces produced empty output
and are excluded, leaving 15 x86 records (5 benign, 10 malicious) and 20 ARM
records (10/10).

\subsection{Feature Representations}

\textbf{Frequency.} Bag-of-syscalls normalized to relative frequencies.
Unresolved kernel pointers (\texttt{syscall\_0x...}) excluded.

\textbf{Bigram (ngram2).} Consecutive syscall pairs as features.

\textbf{Normalized categories.} 131 syscall names mapped to 8 semantic groups
(\texttt{file\_io}, \texttt{network}, \texttt{process}, \texttt{memory},
\texttt{privilege}, \texttt{ipc}, \texttt{timing}, \texttt{sync}) plus
\texttt{other}. Architecture-agnostic: \texttt{mmap}/\texttt{mmap2}
$\to$ \texttt{memory}; \texttt{stat}/\texttt{newfstatat}
$\to$ \texttt{file\_io}. The extended mapping covers 71 previously unmapped
syscalls including \texttt{newfstatat} (83,222 occurrences),
\texttt{fcntl} (48,283), and \texttt{rt\_sig*} family (25,389 combined).

\textbf{Markov transition.} Normalized 9$\times$9 category-to-category
transition matrix (81 features). Each entry records the fraction of
consecutive (category$_i$, category$_j$) pairs in the trace. Fully
architecture-agnostic and sequence-aware.

\subsection{Evaluation Protocol}

\textbf{LOO-CV} for within-arch experiments (Exp A). \textbf{Bootstrap
CI} (200 iterations, resampling x86 training records) for all cross-arch
experiments. Experiment C uses \texttt{StratifiedShuffleSplit} to divide
ARM records 50/50, fixing the degenerate positional split in v1.

\textbf{Experiment A.} LOO-CV yields 53.3\%\,$\pm$\,49.9\%, exposing the prior
single-split 100\% result as a lucky partition. The dataset is too small for
reliable within-arch classification.

\textbf{Experiments B, E.} Raw frequency and bigram features collapse at or
below chance (48.4\%, 49.2\%). Exp B confusion matrix: all 20 ARM samples
predicted benign.

\textbf{Experiment C (fixed).} Stratified split yields 50\%, F1\,=\,0.615
(mostly-malicious predictor). Not production-viable but no longer structurally
degenerate.

\textbf{Experiment D.} Point estimate 55\%; bootstrap mean 48.0\%\,$\pm$\,5.8\%.
Top features: \texttt{ipc} (28.5\%), \texttt{file\_io} (25.4\%),
\texttt{timing} (18.0\%), \texttt{other} (6.5\%). The drop from previously
reported 65\% is attributable to the corrected category mapping reducing
\texttt{other} from 16.3\% to 6.5\% importance (see Section~\ref{sec:rq4}).

\textbf{Experiment F.} Bootstrap mean 53.4\%\,$\pm$\,5.5\%; point estimate
degenerates to all-malicious classifier. Top feature: \texttt{file\_io$\to$ipc}
(17.3\%), reflecting a genuine behavioral pattern. F1\,=\,0.667 at 50\%
accuracy is a precision/recall artifact (malicious-bias on balanced test set).

\textbf{Experiment G.} No improvement from observing more syscalls: accuracy
stays at 50\% for all N\,$\leq$\,1000 and drops to 45\% at N\,$\geq$\,2000.

% -----------------------------------------------------------------------
\section{Discussion}
% -----------------------------------------------------------------------

\subsection{RQ1: Raw, Bigram, and Normalized Features}

None of the three representations produces reliable cross-architecture
detection. Bootstrap means for B (48.4\%), E (49.2\%), and D (48.0\%) are
indistinguishable from chance. The normalization direction is correct in
principle---mapping architecture-specific syscall names to semantic groups is
the appropriate abstraction---but the dataset is too small to confirm it
statistically.

\subsection{RQ2: Markov Transition Features}

Transition features (F) achieve the highest bootstrap mean (53.4\%) of any
cross-arch experiment. The \texttt{file\_io$\to$ipc} transition distinguishes
workloads that cycle through file reads and inter-process communication (typical
of credential harvesting and privilege escalation) from benign workloads
performing sequential I/O. However, the margin over chance is modest and the
point classifier degenerates to all-malicious. Transition features are the
strongest candidate for future work at larger data scales.

\subsection{RQ3: Early Detection}

The early detection curve (G) is flat at 50\% across all N from 50 to 5,000.
The cross-architecture mismatch is structural, not a volume problem: more
syscalls of an ARM trace do not help an x86-trained classifier. This eliminates
``wait for more data'' as a deployment strategy.

\subsection{RQ4: Mapping Completeness}
\label{sec:rq4}

The extended 131-syscall mapping reduces Exp D accuracy from 65\% (prior work)
to 55\%. The cause: unmapped ARM-specific syscalls---especially
\texttt{newfstatat} (83,222 occurrences)---accumulated in \texttt{other},
which acted as an inadvertent ARM-identity detector. Malicious ARM traces
(e.g., \texttt{mal\_privesc\_enum}) issued large numbers of unmapped syscalls,
making \texttt{other} discriminative not for behavioral reasons but for
architectural ones. The corrected mapping eliminates this artifact.

\textbf{Warning for future work:} an incomplete syscall-to-category mapping
can produce inflated cross-architecture accuracy by turning the catch-all
category into an architecture detector.

\subsection{Dataset Scale is the Binding Constraint}

LOO-CV on Exp A (53.3\%\,$\pm$\,49.9\%) establishes that the binding
constraint is dataset scale, not feature representation. Future experiments
should target $\geq$50 samples per architecture from native (non-emulated)
hardware. Sequence-aware models (HMM, 1D CNN) require at minimum this scale
to avoid degeneracy.

\subsection{Practical Recommendations}

\begin{enumerate}
  \item \textbf{Do not assume portability.} x86-trained models achieve
    chance-level on ARM; deploy per-architecture models.
  \item \textbf{Normalize---but validate the mapping.} Category normalization
    is the correct abstraction, but incomplete mappings create artifacts.
    Validate mapping coverage against each target architecture's syscall table.
  \item \textbf{Use Markov transition features.} At the current scale,
    transition features are the most promising representation for future
    cross-architecture work.
  \item \textbf{Collect native ARM data.} QEMU introduces a translation layer;
    native collection is essential before deployment conclusions.
\end{enumerate}

% -----------------------------------------------------------------------
\section{Conclusion}
% -----------------------------------------------------------------------

ArchProbe demonstrates that syscall behavioral signatures are not
architecture-invariant under any tested feature representation at the current
data scale. Bootstrap confidence intervals show all cross-architecture
experiments at 48--53\% accuracy (chance\,=\,50\%). Leave-one-out evaluation
reveals the same-architecture baseline is itself unreliable at N\,=\,15
(53.3\%\,$\pm$\,49.9\%). An extended syscall category mapping (131 syscalls,
up from 60) corrects an artifact that inflated a prior 65\% finding to a more
honest 55\%. Markov transition features are the most promising representation
(bootstrap mean 53.4\%, most interpretable top features) but require
substantially larger datasets to validate.

Three extensions are motivated: (1) $\geq$50 samples per architecture from
native hardware, (2) sequence-aware models (HMM, 1D CNN) requiring that data
scale, (3) a systematic study of mapping completeness across ARM, RISC-V, and
MIPS syscall tables.

The ArchProbe dataset, code, and extended syscall category map are publicly
available at \url{https://github.com/SherbekjonDev/ArchProbe}
(DOI: \href{https://doi.org/10.5281/zenodo.22701078}{10.5281/zenodo.22701078}).
